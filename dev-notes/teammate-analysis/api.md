# API Analyst Report — memorius

**Product:** memorius v0.9.3 — self-contained memory vault for AI agents.
**Repo:** `/home/dimona/Dream-Pixels-Forge/Dev/cli/memorius`
**APIs in scope:** MCP server (`memorius.mcp_server`, ~29 JSON-RPC tools over stdio), FastAPI REST server (`memorius.rest_server`), CLI commands (`memorius.cli.main`, ~40 commands), Python API (`VaultEngine`).
**Docs:** `docs/mcp-server.html`, `docs/rest-api.html`, `docs/cli-reference.html`; prior audit at `dev-notes/teammate-analysis/api.md` (cross-ref, not duplicated).

---

## Scope & Entry Points

- MCP: `McpServer.run()` stdio JSON-RPC loop (`mcp_server.py:255`), `TOOLS` list with `inputSchema`/`required` per tool (`mcp_server.py:60-920`), handlers `tool_memorius_*`.
- REST: `MemoriusAPI._register_routes` (`rest_server.py`): `/health`, `/store`, `/search`, `/mine`, `/status`, `/diary`, `/vault`, `/vaults`, `/diaries`, `/consolidate`, `/extract`, `/factcheck`, `/context`, `/obsidian`, `/contradictions/{id}`, `/memory/{id}`, `/prune`, `/stats`, `/graph/data`, `/graph/view`, `/doctor`, `/memories`, `/metrics`.
- CLI: `argparse` subcommands in `memorius/cli/main.py:main` (`init, setup, status, store, search, mine, diary, diaries, ls, serve, serve-rest, bookcase, config, obsidian, consolidate, extract, factcheck, context, web, profile, stats, delete, get, update, prune, export, import, doctor, repair, list, graph, learn, recall, learnings, apply-learning, learning-stats`).
- Python API: `VaultEngine` (`memorius/vault.py`) — `store/search/get/update/delete/list/consolidate/prune/repair/extract/factcheck/context/profile/learn/recall`.

## Findings (bullets tagged [observation|risk|gap])

### 1. Contracts
- [observation] MCP tools declare `inputSchema` (type object, properties, optional `required`). Examples: `memorius_store` `required: ["content"]`; `memorius_search` `required: ["query"]` with optional `cursor`, `n_results`, `expand_graph`, `rerank`, `tags`; `memorius_delete`/`get`/`update` `required: ["memory_id"]`; `memorius_learn` `required: ["content", "category"]`; `memorius_graph_export` offers `format: ["json","html"]` and `dest`.
- [observation] REST endpoints use JSON request/response bodies; path params for `/memory/{id}` and `/contradictions/{id}`; query params for filtering/pagination.
- [observation] CLI uses argparse positional + optional args (`--vault`, `--shelf`, `--folder`, `--note`, `--ttl`, `--n`, `--limit`, `--cursor`, `--json`).
- [gap] No formal API contract file (OpenAPI/Swagger for REST is auto-generated by FastAPI but not pinned; MCP schemas are inline Python dicts, not a separate spec). Contract stability across versions is not documented.

### 2. Versioning
- [observation] Package version `0.9.3` (`pyproject.toml:15`). MCP `initialize` returns `protocolVersion: "2024-11-05"` (`mcp_server.py`).
- [observation] CHANGELOG.md tracks release history; v0.2.0 and v0.8.2 tool groupings marked "New" — additive-only growth observed, no deprecation/removal noted.
- [gap] No API versioning in URLs or headers (REST is unversioned `/...` paths); no deprecation policy; no sunset dates for old tools/commands.
- [gap] `prometheus_client` imported in `rest_server.py` for `/metrics` but NOT declared in `pyproject.toml` dependencies — `/metrics` returns 503 on fresh installs (contract broken).

### 3. Validation
- [observation] Centralized in `memorius/validation.py`: `validate_name` (`^[a-zA-Z0-9_\-]+$`, max 128), `validate_memory_id` (UUID), `validate_session_id`, `validate_content`. Constants: `MAX_CONTENT_LENGTH=100_000`, `MAX_FIELD_LENGTH=1_000`, `MAX_SEARCH_LIMIT=100`, `MAX_DIARY_CONTENT=50_000`.
- [observation] MCP handlers coerce inputs (`min(n_results, MAX_SEARCH_LIMIT)`, `int/float` casts), convert `ValueError` → `{"error": str(e)}`.
- [gap] MCP handlers `tool_memorius_extract` (`args["conversation"]`) and `tool_memorius_factcheck` (`args["statement"]`) index `args` directly → `KeyError` on missing required field → burns the 10-consecutive-error MCP shutdown cap instead of a clean JSON-RPC invalid-params error. Same pattern in `tool_memorius_context` (`args["query"]`) and `tool_memorius_session_profile` (`args["session_id"]`).
- [gap] `tool_memorius_prune` does `float(args.get("threshold", 0.1))` with no try — non-numeric → exception → consecutive error count.

### 4. Rate limiting
- [observation] REST in-memory sliding-window limiter: 500 requests/minute per IP, 60s window (`rest_server.py:99-102`). Periodic sweep every 200 requests or >10_000 IPs evicts expired entries (`rest_server.py:229-232`). Skips `/health`.
- [gap] Resets on process restart; per-worker multiplication with multiple uvicorn workers (documented in `rest_server.py` class docstring). Not shared across processes.
- [gap] No rate limiting on MCP (stdio) or CLI — single-user/local assumption.
- [gap] No rate-limit headers (`Retry-After`, `X-RateLimit-*`) in REST responses.

### 5. Docs
- [observation] `docs/mcp-server.html` — all 29 tools + per-agent client config snippets. `docs/rest-api.html` — full endpoint table, auth, rate limits, daemon mode, TLS. `docs/cli-reference.html` — every subcommand and flag.
- [gap] Docs are static HTML; no evidence they're auto-generated from code, so drift between docs and implementation is possible (e.g. endpoint tables vs actual routes).
- [gap] No OpenAPI/Swagger UI hosted; MCP schema discoverable only at runtime via `tools/list`.

### 6. Deprecation
- [observation] Tool/command growth appears additive-only (v0.2.0 "New" tools, v0.8.2 "New" learning tools). No deprecated tools/commands found.
- [gap] No deprecation policy, no sunset schedule, no `@deprecated` markers in code.

### 7. Error shapes
- [observation] MCP: JSON-RPC errors (`-32700` parse, `-32601` method not found). Tool failures return `{"error": "..."}` dicts as success-response content text — callers must parse text to detect errors.
- [observation] REST: `HTTPException` / `raise e` → JSON error responses; sanitizing 500 exception handler.
- [observation] CLI: `print(f"Error: …")` and return; unknown commands print "Unknown command:" with no non-zero exit (`cli/main.py:~1170`).
- [gap] Inconsistent error shapes across MCP (`{"error":...}` text blobs) vs REST (HTTP status + JSON) vs CLI (plain text).

### 8. Content limits
- [observation] `MAX_SEARCH_LIMIT=100` caps `n_results`/`limit` in MCP and REST. `MAX_CONTENT_LENGTH=100KB` enforced via REST `size_limit_middleware` (413 on oversized) and MCP content-length checks. `bookcase.js` caps rendered books at `MAX_BOOKS=1000`.
- [observation] Vectors stripped from all MCP/REST/CLI responses by design (`{k: v for k, v in m.to_dict().items() if k != "vector"}`; `d.pop("vector", None)` in REST).

## Highlights (3-5 short)

1. MCP exposes ~29 JSON-RPC tools with inline `inputSchema`/`required` validation; vectors stripped from all responses.
2. REST has opt-in `MEMORIUS_API_KEY` auth, 500 req/min/IP sliding-window rate limits, 100KB body cap, CORS restricted to loopback/Obsidian.
3. No formal API contract file (OpenAPI/Swagger not pinned; MCP schemas inline), no API versioning, no deprecation policy.
4. `/metrics` (Prometheus) is referenced in code but `prometheus_client` is not a declared dependency — broken contract on fresh install.
5. Error shapes are inconsistent: MCP `{"error":...}` text blobs vs REST HTTP+JSON vs CLI plain text.

---

## Domain summary

memorius exposes three APIs around a single `VaultEngine`: a stdio MCP server with ~29 validated JSON-RPC tools (inputSchema/required per tool, vectors excluded from responses), a FastAPI REST server with opt-in API-key auth, per-IP sliding-window rate limits, CORS restricted to loopback/Obsidian, and 100KB body caps, and an argparse CLI with ~40 commands plus optional `--json` machine output. There is no formal API contract file (OpenAPI not pinned; MCP schemas are inline Python dicts), no API versioning, and no deprecation policy. The clearest contract bug: `/metrics` references `prometheus_client` which is not a declared dependency. Error shapes are inconsistent across the three APIs.
