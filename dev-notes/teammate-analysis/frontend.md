# Frontend Analyst Report — memorius

**Subject:** memorius v0.9.3 — a Python memory vault for AI agents (NOT a web SPA)
**Repo:** `/home/dimona/Dream-Pixels-Forge/Dev/cli/memorius`
**Interfaces in scope:** CLI (`memorius.cli.main`), MCP server (`memorius.mcp_server`, ~29 JSON-RPC tools over stdio), FastAPI REST server (`memorius.rest_server`), agent hooks (`memorius/hooks/`), and the 3D browser "bookcase" UI (`memorius/bookcase/`, loopback HTTP on 8912/8400).

---

## Scope & Entry Points

Entry points are declared in `pyproject.toml` under `[project.scripts]`:

- `memorius = "memorius.cli.main:main"` — the CLI (also reachable as `python -m memorius.cli.main`).
- `memorius-hook = "memorius.hooks.cli:main"` — agent hook lifecycle (stdin JSON in, JSON decision out).
- `memorius-plugin-gen = "memorius.plugin_gen.cli:main"` — per-agent MCP manifest generator.
- `memorius-normalize = "memorius.normalizers.cli:main"` — conversation-format importers.

There is no web SPA frontend. The only browser-facing surface is the 3D bookcase, served over loopback HTTP. All four user-facing interfaces (CLI, MCP, REST, bookcase) share one `VaultEngine` instance (`memorius/vault.py`, `class VaultEngine`, `__init__` at line ~45), created in `main()` (`cli/main.py` line 369: `engine = VaultEngine(config)`) and handed to `McpServer(engine)` (`mcp_server.py`, `cmd_serve` at cli/main.py line 669) and `MemoriusAPI(engine)` (`rest_server.py`, `cmd_serve_rest` at cli/main.py line 677).

Config lives at `~/.memorius/config.yaml` (or cwd `memorius.yaml`), loaded by `memorius/config.py:load_config()`; defaults documented in `DEFAULT_CONFIG_YAML` (config.py line ~34): `server.rest_port: 8912`, `server.host: "127.0.0.1"`, `storage.path: ~/.memorius/data`.

## Findings (bullets tagged [observation|risk|gap])

### 1. CLI surface

- **Command set.** `memorius.cli.main:main` builds a single `argparse.ArgumentParser` with subcommands (cli/main.py line ~44): `init, setup, status, store, search, mine, diary, diaries, ls, serve, serve-rest, bookcase, config, obsidian, consolidate, extract, factcheck, context, web, profile, stats, delete, get, update, prune, export, import, doctor, repair, list, graph (view/export-html/stats/json), obsidian (list/import/export), learn/recall/learnings/apply-learning/learning-stats`. Global flags: `--version`, `--config`, `--debug`. The top-of-file docstring (cli/main.py lines ~6-50) doubles as the command reference. [observation]
- **Arg parsing.** Standard `argparse` with positional args (e.g. `store <content>`, `search <query>`, `delete <memory_id>`) and options (`--vault`, `--shelf`, `--folder`, `--note`, `--ttl`, `--n`, `--limit`, `--cursor`). Required-only where enforced: `learn --category` (choices enum), `obsidian`/`graph` use nested subparsers. Unknown commands fall through to `print(f"Unknown command: {args.command}")` (cli/main.py line ~1170) — no non-zero exit. [observation][gap]
- **Text vs `--json` output.** `--json` (dest `output_json`) is offered on `status`, `stats`, `get`, `update`, `prune`, `learnings`, `learning-stats`, and `repair`. When set, `print(json.dumps(..., indent=2, sort_keys=True))` writes one JSON object to stdout; text path is unchanged. Verified by tests/test_cli_json_flag.py: sorted keys at every level, deterministic byte-identical output, doctor warnings are data (exit 0), non-zero only on real errors (e.g. unreadable store). [observation]
- **stdin fallback.** Commands that take content/query read `sys.stdin.read().strip()` when the positional is absent: `store`, `search`, `mine`, `extract`, `factcheck`, `context`, `web`, `recall`, `learn`. Empty after read → "Error: … required" and return (no exception). [observation]
- **Interactive prompts / input() / EOFError.** `input()` is used in four places (cli/main.py: `diary` session_id/title/summary at lines ~616-621, `profile` session_id at ~1099, `recall` query at ~1492, `delete` confirmation at ~1437). `delete` wraps `input()` in try/except EOFError → "Aborted (no confirmation)." and returns (cli/main.py ~1444); `diary`/`profile`/`recall` do NOT catch EOFError, so a piped/non-interactive stdin raises and crashes the command. [observation][risk]
- **Logging.** `logging.basicConfig(level=logging.WARNING, …)` at cli/main.py line ~33; `--debug` raises memorius logger to DEBUG (line ~1166). Emoji/icons used in factcheck verdicts (`✅❌⚠️❓`, cli/main.py ~1330) and `_ensure_utf8_streams()` force-UTF8s stdout/stderr with `errors="replace"` (cli/main.py ~50) to survive cp1252 consoles. [observation]

### 2. MCP server

- **JSON-RPC loop over stdio.** `McpServer.run()` (mcp_server.py line ~255) reads `sys.stdin.readline()` in a `while True`, parses `json.loads`, dispatches via `_handle_request`, writes `json.dumps(response) + "\n"` to `sys.stdout` and flushes. `EOFError` breaks the loop; `json.JSONDecodeError` increments a consecutive-error counter and shuts down after 10 (mcp_server.py ~275-289). [observation]
- **stdout/stderr separation.** Startup banner goes to stderr (`cmd_serve`: `print("memorius MCP server starting (stdio)…", file=sys.stderr)`, cli/main.py ~693). However, `run()` reconfigures the `memorius` logger to emit JSON log lines to **stdout** (mcp_server.py ~263-272, `StreamHandler(sys.stdout)`), so operational logs share the same fd as JSON-RPC responses — a parsing hazard for stdio clients. [risk]
- **Methods.** `initialize` (returns `protocolVersion: "2024-11-05"`, `capabilities: {"tools": {}}`, `serverInfo`), `notifications/initialized` (→ null), `tools/list` (returns `self.TOOLS`), `tools/call` (dispatches to `tool_<name>`), unknown method → `-32601`. [observation]
- **Tool inputSchema/required.** ~29 tools in `TOOLS` (mcp_server.py ~60-920). Each declares `inputSchema` (type object, properties, optional `required`). Examples: `memorius_store` `required: ["content"]`; `memorius_search` `required: ["query"]` with optional `cursor`, `n_results`, `expand_graph`, `rerank`, `tags`; `memorius_delete`/`memorius_get`/`memorius_update` `required: ["memory_id"]`; `memorius_learn` `required: ["content", "category"]`; `memorius_graph_export` offers `format: ["json","html"]` and `dest`. Handlers validate required keys with `args["..."]` (KeyError if missing — e.g. `tool_memorius_extract` `args["conversation"]` at mcp_server.py ~646, `tool_memorius_factcheck` `args["statement"]` at ~660). [observation][gap]
- **Vector excluded from responses.** Every handler that returns a `Memory` strips the vector: `{k: v for k, v in m.to_dict().items() if k != "vector"}` (search mcp_server.py ~580, get ~725, update ~750, delete/contradictions ~690-705, recall ~845, learnings ~875) and `d.pop("vector", None)` in REST. Stated intent in search description: "Exclude vector from response — it's large and not useful to callers" (mcp_server.py ~578). [observation]
- **Single-instance guard.** `cmd_serve` runs `acquire_serve_lock(config, reclaim=args.reclaim)` before opening the vault; `ServeAlreadyRunningError` → message + `SystemExit(1)` (cli/main.py ~1150-1165, memorius/single_instance.py). `--reclaim` takes over an orphaned instance. [observation]

### 3. REST server

- **Endpoints** (memorius/rest_server.py, `MemoriusAPI._register_routes`): `GET /health`, `GET /health/live`, `GET /health/ready`; `POST /store`; `POST /search`; `POST /mine`; `GET /status`; `POST /diary`; `GET /vault`; `GET /vaults` (powers the bookcase); `GET /diaries`; `POST /consolidate` (requires `confirm=true`); `POST /extract`; `POST /factcheck`; `POST /context`; `GET /obsidian`; `POST /obsidian/import` (confirm/dry_run); `POST /obsidian/export`; `GET /contradictions/{memory_id}`; `GET /memory/{memory_id}`; `PATCH /memory/{memory_id}`; `DELETE /memory/{memory_id}`; `POST /prune`; `GET /stats`; `GET /graph/data`; `GET /graph/view` + `GET /visualize` (HTML); `GET /doctor`; `GET /memories` (cursor pagination); `GET /metrics` (Prometheus, if `prometheus_client` installed — note: `prometheus_client` is used but NOT declared in pyproject.toml dependencies). [observation][gap]
- **Auth.** `MEMORIUS_API_KEY` env var; when set, every path except `/health` requires `Authorization: Bearer <key>` compared with `hmac.compare_digest` (timing-safe). Missing/invalid → 401. Warning if key < 16 chars (rest_server.py ~162-176). When unset, auth is disabled and a warning is printed only when binding to non-localhost (rest_server.py ~791-801). No read/write distinction, no RBAC. [observation][risk]
- **Rate limits.** In-memory sliding-window limiter (`self._request_counts: dict[str, list[float]]`), 500 requests/minute per IP, 60s window (rest_server.py ~99-102). Periodic sweep every 200 requests or when >10_000 IPs tracked evicts fully-expired entries (rest_server.py ~229-232). **Resets on process restart; per-worker multiplication with multiple uvicorn workers** (documented in class docstring rest_server.py ~85-90). Skips `/health`. [observation]
- **Request size.** `MAX_CONTENT_LENGTH` (100KB) enforced via `content-length` header and chunked stream accumulation (rest_server.py `size_limit_middleware`, ~195-222); 413 on oversized. [observation]
- **Daemon mode.** `serve-rest --daemon` launches a detached subprocess (`subprocess.Popen`, `start_new_session` on Unix / `DETACHED_PROCESS` on Windows, stdin/out/err to DEVNULL) via `python -c` script that writes its own PID file; parent writes pid_file from `proc.pid`. `--stop` reads PID file and signals the process; `--pid-file` defaults to `~/.memorius/serve.pid`. [observation]
- **TLS.** `serve-rest --tls-cert <PEM> --tls-key <PEM>` passed to `uvicorn.run(ssl_certfile=…, ssl_keyfile=…)` (rest_server.py `run_rest_server` ~773-816, cli/main.py ~872-913). Warning if only one of cert/key supplied; "TLS: enabled" printed when both present. Plaintext HTTP is the default. [observation]
- **CORS.** `allow_origin_regex=r"^https?://(127\.0\.0\.1|localhost)(:\d+)?$"` plus `app://obsidian.md` (rest_server.py ~145-150) — covers dynamic loopback ports. [observation]
- **Host default.** Binds `127.0.0.1` by default; warning logged when bound to non-localhost without API key. [observation]

### 4. Bookcase 3D UI

- **Tech stack.** Vanilla HTML/CSS/JS modules under `memorius/bookcase/`, shipped as package data (`pyproject.toml` `[tool.setuptools.package-data] memorius = ["data/*", "bookcase/*"]`, include-package-data = true). `bookcase.html` imports Three.js 0.160.0 from `unpkg.com` CDN via importmap (bookcase.html ~40-44) with **no SRI hash and no local fallback**; a 4s fallback status pill fires if `window.__bcBooted` is not set (bookcase.html ~165-178). Web Speech API (`speechSynthesis` + `SpeechRecognition`) for TTS/stt (bookcase-librarian.js). No build step — raw browser assets served directly. [observation][risk]
- **Files.** `bookcase.html` (page skeleton + DOM contract header comment), `bookcase.css` (dark/cinematic, orange accent), `bookcase.js` (bootstrap + data flow + UI wiring), `bookcase-scene.js` (Three.js scene), `bookcase-walk.js` (first-person controls), `bookcase-layout.js` (floor-plan math), `bookcase-librarian.js` (voice guidance). All ≤500 lines (enforced by tests/test_bookcase.py). [observation]
- **Controls.** `WalkControls` (bookcase-walk.js): WASD/arrow-key walking at `EYE_Y = 1.65` (bookcase-layout.js), mouse look via `requestPointerLock()` (pointer-lock) with click-drag drag-look fallback, axis-separated AABB collision so the camera cannot pass through shelves (`collides()`), `p.y = eyeY` clamp so it never leaves walking height. `bookcase-scene.js` drives camera flights (`flyTo` on search hit, `resetView` to spawn). [observation]
- **Librarian TTS toggle.** `#bc-librarian` checkbox (bookcase.html ~133); `Librarian.enabled` toggles `speechSynthesis.speak` while `say()` **always** renders to the `#bc-guidance` log (`role="log"`, `aria-live="polite"`), so guidance stays visible as text when voice is off (bookcase-librarian.js `say`, ~108-121). Hold-to-talk mic (`#bc-mic`, Chromium `webkitSpeechRecognition`/`SpeechRecognition`); disabled gracefully elsewhere; voice picker populated from `speechSynthesis.getVoices()`, choice persisted in `localStorage` key `bc-voice`. [observation]
- **Loopback-only claim.** `cmd_bookcase` binds both servers to `127.0.0.1` only (cli/main.py `cmd_bookcase` ~760-850): starts/reuses REST at `http://127.0.0.1:<port>` (default 8912) after a `/health` poll (falls back to in-process uvicorn thread), serves bookcase assets via `http.server.ThreadingHTTPServer(("127.0.0.1", static_port))` (default static 8400), prints `http://127.0.0.1:8400/bookcase.html?api=http://127.0.0.1:8912`, opens browser unless `--no-browser`, blocks on `signal`/Ctrl-C, then shuts down and calls `engine.close()`. README: "Everything is loopback-only — nothing leaves your machine." The claim holds at the bind-address level; there is no additional firewall/auth on the static server (directory listing enabled — see risk). [observation][risk]
- **API contract the page depends on.** `GET /vaults`, `GET /vault?vault=`, `GET /memories?limit=100&cursor=` (cursor pagination, capped `MAX_BOOKS=1000` in bookcase.js ~11), `POST /search`, `GET /memory/{id}` — all referenced in bookcase.js (tests/test_bookcase.py asserts these substrings). [observation]
- **Ports.** REST default 8912 (`config.py` `rest_port: 8912`), static asset default 8400; both overridable via `--port`/`--static-port` and `MEMORIUS_REST_PORT` env. MCP stdio port `8911` exists in config (`mcp_port: 8911`) but is informational for stdio (cli/main.py `serve --port` "Not used for stdio"). [observation]

### 5. State

- **Shared VaultEngine.** CLI (`cmd_*` handlers), MCP (`McpServer(engine)`), REST (`MemoriusAPI(engine)`), and hooks (`HookEngine` constructs its own `VaultEngine` via `load_config()`, hooks/engine.py) all operate on the same storage through one engine per process. No cross-process shared memory — each process opens its own SQLite/Chroma connections; single-instance guard serializes `serve`. [observation]
- **In-memory caches / lazy singletons.** `VaultEngine` lazily initializes and caches `_search_mod`, `_search_mod_episodic`, `_store_mod_semantic`, `_store_mod_episodic`, `_store_mod` (vault.py ` _get_*` methods); `ConsolidationDaemon` runs as a background thread when `consolidation.enabled` (vault.py `__init__` ~130-140, `close()` stops/joins it). REST rate-limiter state `_request_counts` lives per-process (rest_server.py ~99). No persistent in-memory cache across restarts; state is durable in SQLite + vector store. [observation]
- **Session/profile state.** `memorius/session.py`: `SessionProfile` dataclass, `build_session_profile()` (from recent diaries + memories), `inherit_from_previous_session()`, `format_profile_for_context()`. Exposed via CLI `profile` (cli/main.py ~1090-1105) and MCP `memorius_session_profile`. Diaries stored in `SQLiteStore` and listed via `engine._meta.list_diaries`. Hooks persist per-session state to `~/.memorius/hook_state/*_state.json` (hooks/cli.py `cmd_status`). [observation]

### 7. Performance

- **Cursor/limit pagination.** `GET /memories?limit=&cursor=` (REST, rest_server.py ~711; cap `min(limit, 100)`), CLI `memorius list --limit (default 10) --cursor` (cli/main.py ~235-239, ~1386-1402), MCP `memorius_list` (`limit` default 10, capped `MAX_SEARCH_LIMIT`, `cursor` passthrough, mcp_server.py ~811-820). Backend `meta_store.list_memories_meta` uses composite cursor `"timestamp~memory_id"` (meta_store.py ~760-832). `VaultEngine.list_memories` merges episodic + semantic and re-applies the limit, using the semantic store's `next_cursor` — noted in-code as a simplification ("In a more sophisticated implementation, we'd need to merge cursors properly", vault.py ~429-430). [observation][gap]
- **Caps.** `validation.py`: `MAX_CONTENT_LENGTH = 100_000` (100KB), `MAX_FIELD_LENGTH = 1_000`, `MAX_SEARCH_LIMIT = 100`, `MAX_DIARY_CONTENT = 50_000`. Enforced in MCP (search `n_results`, `list` limit, content/transcript length), REST (`/search` query length, `/store` content, `/mine` text, `/diary` content), and CLI via engine validation. `bookcase.js` caps rendered books at `MAX_BOOKS = 1000` (line ~11) and fetches pages of 100. [observation]
- **Rate-limiter sweep.** Prevents unbounded growth of `_request_counts` (rest_server.py ~229-232), but still per-process and in-memory. [observation]

### 8. Accessibility

- **CLI color/logging.** Plain text + emoji factcheck verdicts; no ANSI color codes found; logging to stderr/stdout at WARNING by default; UTF-8 stream reconfigure with replacement errors. `--json` gives stable, parseable output for tooling (sort_keys, single object). [observation]
- **JSON for tooling.** `--json` on status/stats/get/update/prune/learnings/learning-stats/repair; MCP returns `{"content": [{"type": "text", "text": json.dumps(result)}}]` for every tool; REST returns JSON everywhere. [observation]
- **Bookcase keyboard/screen-reader.** `#bc-status` `role="status"`; `#bc-guidance` `role="log" aria-live="polite"` with every librarian utterance also written as text; `#bc-mic` `aria-label="Hold to talk"`; detail panel toggles `hidden`; search submits on Enter; `WalkControls` ignores keydown when focus is inside `INPUT/TEXTAREA/SELECT/contenteditable` (bookcase-walk.js ~75-79) so typing in the search box doesn't walk the camera; `escapeHtml()` used for all dynamic markup (bookcase.js ~177-185) and `textContent` for book content (bookcase.js ~225). No focus traps, no skip links, no `prefers-reduced-motion` handling, canvas/WebGL has no ARIA alternative, and the 3D scene is inherently pointer-driven — keyboard-only navigation of the bookcase is limited to search/controls, not movement through the scene. [observation][gap]

## Highlights (3-5 short)

1. One `VaultEngine` backs CLI, MCP, REST, and hooks; the bookcase is a separate loopback browser UI that talks to the REST API, not to the engine directly.
2. `--json` output is deterministic and sorted (status/stats/get/update/prune/learnings/learning-stats/repair), with warnings as data and exit 0 — suitable for tooling.
3. The MCP server strips `vector` from every tool response and runs a strict JSON-RPC stdio loop, but writes JSON-format logs to the same stdout fd as responses.
4. The bookcase binds only to `127.0.0.1` (REST 8912 + static 8400) and relies on Three.js from unpkg CDN without SRI or offline fallback — the loopback claim holds at the network level but the CDN dependency and open static server weaken it.
5. Pagination caps (`MAX_SEARCH_LIMIT=100`, `MAX_CONTENT_LENGTH=100KB`, `MAX_BOOKS=1000`) exist, but rate limiting is per-process/in-memory and REST auth is opt-in via `MEMORIUS_API_KEY`.

## Domain summary

memorius presents four frontends around a single `VaultEngine`: a text CLI with optional `--json` machine output and `input()`-based interactive prompts, a stdio MCP server exposing ~29 validated JSON-RPC tools that deliberately exclude embedding vectors from responses, a FastAPI REST server (loopback-default, opt-in API-key auth, per-IP sliding-window rate limits, optional TLS, Prometheus metrics), and a loopback-only Three.js bookcase with WASD/pointer-lock navigation and a Web-Speech librarian whose utterances are mirrored to a live-log region for screen-reader accessibility. Packaging ships raw browser assets with no build step, relies on loose dependency pins with no lockfile, and caps search/content sizes at fixed constants. The clearest gaps: MCP logs share stdout with JSON-RPC frames, REST auth/rate-limit are per-process and opt-in, the bookcase depends on an unpkg CDN without SRI, and several `input()` call sites don't handle `EOFError`. Suggested canonical home for frontend cross-cutting notes: `dev-notes/teammate-analysis/frontend.md` (this file).
