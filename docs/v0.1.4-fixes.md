## Fix 1 (CRITICAL): Database Migration Crash

**File:** `memorius/vault.py` — `SQLiteStore._init_db()`

### Problem

When upgrading from v0.1.2 (or earlier) to v0.1.3+, an existing `memorius.db` crashes on startup with:

```
sqlite3.OperationalError: no such column: vault
```

**Root cause:** Schema changed between versions (old had `diaries.palace`, new expects `diaries.vault`). The `CREATE TABLE IF NOT EXISTS` silently skips the existing table, then `CREATE INDEX ON diaries(vault)` fails.

### Fix

Add three methods to `SQLiteStore`:

1. `_migrate_diaries_table()` — renames `palace` → `vault` in `diaries` table
2. `_migrate_hierarchy()` — copies `palaces/wings/rooms/drawers` → `vaults/shelves/folders/notes`
3. Updated `_init_db()` — runs migration before creating indexes

```python
def _init_db(self):
    conn = self._conn()
    with self._lock:
        # Step 1: Detect and migrate old diaries schema
        self._migrate_diaries_table(conn)

        # Step 2: Create new tables (no-op if already exist)
        conn.executescript("""
            CREATE TABLE IF NOT EXISTS vaults (...);
            CREATE TABLE IF NOT EXISTS shelves (...);
            CREATE TABLE IF NOT EXISTS folders (...);
            CREATE TABLE IF NOT EXISTS notes (...);
            CREATE TABLE IF NOT EXISTS diaries (
                id TEXT PRIMARY KEY, session_id TEXT NOT NULL,
                vault TEXT NOT NULL DEFAULT 'main',
                title TEXT DEFAULT '', summary TEXT DEFAULT '',
                content TEXT DEFAULT '', exchange_count INTEGER DEFAULT 0,
                created_at TEXT NOT NULL, updated_at TEXT NOT NULL
            );
        """)
        conn.commit()

        # Step 3: Migrate old hierarchy data
        self._migrate_hierarchy(conn)

        # Step 4: Create indexes (safe after migration)
        conn.executescript("""
            CREATE INDEX IF NOT EXISTS idx_diaries_session ON diaries(session_id);
            CREATE INDEX IF NOT EXISTS idx_diaries_vault ON diaries(vault);
            CREATE INDEX IF NOT EXISTS idx_folders_hierarchy ON folders(vault, shelf);
            CREATE INDEX IF NOT EXISTS idx_notes_hierarchy ON notes(vault, shelf, folder);
        """)
        conn.commit()

def _migrate_diaries_table(self, conn: sqlite3.Connection):
    """Rename diaries.palace -> diaries.vault if old schema detected."""
    cur = conn.execute("PRAGMA table_info(diaries)")
    cols = {row["name"] for row in cur.fetchall()}
    if "palace" in cols and "vault" not in cols:
        logger.warning("Detected old diaries schema (palace column) — migrating...")
        conn.executescript("""
            PRAGMA foreign_keys=OFF;
            CREATE TABLE diaries_new (
                id TEXT PRIMARY KEY, session_id TEXT NOT NULL,
                vault TEXT NOT NULL DEFAULT 'main',
                title TEXT DEFAULT '', summary TEXT DEFAULT '',
                content TEXT DEFAULT '', exchange_count INTEGER DEFAULT 0,
                created_at TEXT NOT NULL, updated_at TEXT NOT NULL
            );
            INSERT INTO diaries_new
                SELECT id, session_id, palace, title, summary,
                       content, exchange_count, created_at, updated_at
                FROM diaries;
            DROP TABLE diaries;
            ALTER TABLE diaries_new RENAME TO diaries;
            PRAGMA foreign_keys=ON;
        """)
        conn.commit()
        logger.info("Migrated diaries table: palace -> vault")

def _migrate_hierarchy(self, conn: sqlite3.Connection):
    """Migrate old palaces/wings/rooms/drawers to vaults/shelves/folders/notes."""
    cur = conn.execute(
        "SELECT name FROM sqlite_master WHERE type='table' AND name='palaces'"
    )
    if not cur.fetchone():
        return  # already on new schema
    logger.warning("Detected old hierarchy — migrating...")
    for p in conn.execute("SELECT * FROM palaces"):
        conn.execute("INSERT OR IGNORE INTO vaults ...", (p["name"], ...))
        for w in conn.execute("SELECT * FROM wings WHERE palace=?", (p["name"],)):
            conn.execute("INSERT OR IGNORE INTO shelves ...", (p["name"], w["name"], ...))
            for r in conn.execute("SELECT * FROM rooms WHERE palace=? AND wing=?", (p["name"], w["name"])):
                conn.execute("INSERT OR IGNORE INTO folders ...", (p["name"], w["name"], r["name"], ...))
                for d in conn.execute("SELECT * FROM drawers WHERE palace=? AND wing=? AND room=?", ...):
                    conn.execute("INSERT OR IGNORE INTO notes ...", ...)
    conn.commit()
    logger.info("Hierarchy migrated: palaces/wings/rooms/drawers -> vaults/shelves/folders/notes")
```

## Fix 4 (MEDIUM): Thread-Local DB Connections Never Closed

**File:** `memorius/vault.py` — `SQLiteStore`

### Problem

`SQLiteStore._conn()` uses `threading.local()` to store a connection per thread, but connections are never closed when a thread exits. In long-running applications (MCP server, REST server), this leaks file descriptors.

### Fix

Add a `close_thread_connection()` classmethod and register it as a thread cleanup hook:

```python
@classmethod
def close_thread_connection(cls):
    """Close the calling thread's connection, if open."""
    if hasattr(local, "memorius_conn") and local.memorius_conn:
        try:
            local.memorius_conn.close()
        except Exception:
            pass
        local.memorius_conn = None

# Register thread cleanup (Python 3.8+)
import threading
threading._register_atexit(cls.close_thread_connection)  # noqa
```

Alternatively, use a simpler approach: make `VaultEngine` a context manager that closes connections:

```python
class VaultEngine:
    def close(self):
        self._meta.close()
        self._vector = None

    def __enter__(self):
        return self

    def __exit__(self, *args):
        self.close()
```

Use in MCP/REST servers:

```python
# mcp_server.py — at startup
import atexit
atexit.register(lambda: engine.close())
```

## Fix 5 (MEDIUM): REST Server Has No Graceful Shutdown

**File:** `memorius/rest_server.py`

### Problem

`uvicorn.run()` blocks forever with no signal handler. The server cannot be stopped gracefully (e.g., via SIGTERM).

### Fix

```python
def run_rest_server(engine, host="127.0.0.1", port=8912):
    from fastapi import FastAPI
    import uvicorn

    app = FastAPI(title="Memorius API", version=_memorius_version)

    @app.on_event("shutdown")
    async def shutdown():
        engine.close()

    # ... routes unchanged ...

    config = uvicorn.Config(app, host=host, port=port, log_level="info")
    server = uvicorn.Server(config)
    try:
        server.run()
    except KeyboardInterrupt:
        pass
    finally:
        engine.close()
```

## Fix 9 (LOW): Config Env Vars Don't Support Booleans

**File:** `memorius/config.py` — `_coerce()`

### Problem

`MEMORIUS_HOOKS_ENABLED=false` would be coerced to `int(0)` or left as string `"false"`, never as a Python `bool`.

### Fix

```python
def _coerce(val: str) -> int | bool | str:
    """Coerce string to int or bool if possible, else return as-is."""
    if val.lower() in ("true", "yes", "1"):
        return True
    if val.lower() in ("false", "no", "0"):
        return False
    try:
        return int(val)
    except ValueError:
        return val
```

## Fix 11 (LOW): Confusing Double-Dispatch for Obsidian

**File:** `memorius/cli/main.py` — `cmd_obsidian()` and `memorius/cli/obsidian.py` — `cmd_obsidian()`

### Problem

Two functions named `cmd_obsidian` exist — one in `main.py` that imports and calls the other in `obsidian.py`. This is confusing for debugging and makes stack traces harder to read.

### Fix

Either:
- **Option A:** Inline the dispatch logic in `main.py` directly instead of calling into `obsidian.py`
- **Option B:** Rename the one in `obsidian.py` to `dispatch()` and keep `main.py`'s as a thin wrapper

**Recommended (Option B):**

In `obsidian.py`:
```python
def dispatch(engine, args, config):
    """Main entry point — called from CLI main()."""
    ...
```

In `main.py`:
```python
def cmd_obsidian(engine, args, config):
    from memorius.cli.obsidian import dispatch
    dispatch(engine, args, config)
```

## Fix 12 (LOW): Integration Tests Assume `/usr/bin/memorius`

**File:** `tests/test_integration.py`

### Problem

`BIN_DIR = Path(sys.executable).parent` resolves to `/usr/bin/` when running under the system Python, but `memorius` is installed via pipx at `~/.local/bin/memorius`. All integration tests that call `run_memorius()` fail with:

```
FileNotFoundError: [Errno 2] No such file or directory: '/usr/bin/memorius'
```

### Fix

```python
import shutil

def run_memorius(*args, env=None, input_text=None, timeout=120):
    """Run the memorius CLI and return stdout, stderr, exit_code."""
    memorius_bin = shutil.which("memorius")
    if not memorius_bin:
        pytest.skip("memorius not found in PATH")
    cmd = [memorius_bin] + list(args)
    ...
```

Or use the in-process API instead of subprocess (cleaner):

```python
def run_memorius(*args, **kwargs):
    """Run memorius CLI in-process (no subprocess)."""
    from memorius.cli.main import main
    import sys, io

    old_argv = sys.argv
    old_stdout = sys.stdout
    sys.argv = ["memorius"] + list(args)
    sys.stdout = io.StringIO()

    try:
        try:
            main()
        except SystemExit:
            pass
        output = sys.stdout.getvalue()
        return output, "", 0
    finally:
        sys.argv = old_argv
        sys.stdout = old_stdout
```
